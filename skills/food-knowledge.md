# food-knowledge — 综合资料检索

通过 `POST /food-knowledge/search` 跨来源寻找主题相关资料。适合“查一下槲皮素相关研究和食品应用资料”等未限定单一来源的请求。它返回资料卡片和阅读链接，不是全部专业详情工具的 REST 入口。

## 请求

沿用 `SKILL.md` 的基础地址、`dk_api`、鉴权和版本请求头。

```bash
dk_api POST "food-knowledge/search" \
  '{"keyword":"槲皮素"}'
```

- 只发送 `keyword`，去除首尾空白后非空，最多 200 个字符；请求体最大 4 KiB。
- 保留用户指定的主题、实体和限定信息；不能无依据改成另一成分、标准或结构编号。无法确定检索关键词时先澄清。
- 不支持来源过滤、详情 ID、`limit` 或分页游标，不自行添加这些参数。
- 用户明确限定知识库、食品伙伴网或某个网站时，使用相应入口，不以综合搜索代替。

## 覆盖范围

后端会聚合已配置的 Food 检索工具、部分科研来源显式适配、食品伙伴网、受控官网搜索，以及 `DEEPKNOW_KB_ID` 指定知识库内当前用户可访问、解析完成且启用的公众号文章。公众号分支不是全网公众号搜索。

来源可涉及食品法规、标准、文献、化合物、中药、靶点及疾病相关资料。实际执行受来源开关、账号权限、参数适配、域名白名单和服务状态限制；部分来源要求明确实体类型或标识，不能承诺任意关键词覆盖所有 MCP 来源。

后端聚合和既有官网兜底属于该接口内部行为。Skill 不自行并发追加其他入口，不因某来源失败自动换源。此接口不提供 MCP 的全部详情、关联网络或临床试验结果操作。

## 响应与状态

外层为 `{"success":true,"data":...}`，读取 `response.data`：

| 字段 | 含义 |
|---|---|
| `keyword` | 本次关键词 |
| `status` | `complete`、`partial` 或 `unavailable` |
| `items[]` | 资料卡片；保留返回顺序 |
| `total` | 本次最终返回条数，不是上游数据库总量 |
| `tool_summary` | Food 工具的发现、执行、成功、跳过和失败数量，不代表所有聚合分支 |
| `degraded[]` | 可选的降级摘要，包含来源及失败原因等信息 |

- `complete`：本次执行未报告降级，不代表全库、全文或全部数据源都已检索。
- `partial`：有部分结果或来源降级，说明当前覆盖不完整；仅使用实际返回的卡片。
- `unavailable`：无成功分支，说明本次无法取得可靠结果，不把 HTTP 200 当作检索成功。
- `items` 为空时如实报告无可展示资料，并结合状态区分空结果与服务不可用。
- 最终 `items` 没有固定 10 条总上限，但各来源仍可能限量、超时或被过滤；接口没有分页能力，不宣称返回全量记录。
- `warnings`、`limitations` 当前不直接公开，不能编造这些响应字段或其中的内容。

## 资料展示与引用

卡片常用字段：`title`、`provider`、`source_type`、`label`、`identifier`、`url`、`official_links`、`source_organization`、`regulatory_authority`、`jurisdiction`、`retrieved_at`、`language`、`match_basis`。

- 展示资料标题、来源类别和返回的阅读链接；日期、标识、监管机构等只在实际返回时使用。
- `official_links[]` 含 `type`、`label`、`url`、`primary`。字段名称不保证每条都是官方法规，须结合来源区分官网、科研数据库和公众号文章。
- 只使用卡片返回的有效 `url` 或 `official_links[].url`，不从标识拼接链接。没有链接时保留文字来源，不制造引用。
- 卡片证明找到相关资料，不能仅凭标题推导法规结论、添加量、疗效、实验数值或因果关系。需要正文而当前响应没有时，明确证据不足，不声称已读全文。
- 返回的阅读链接不一定在 Firecrawl 白名单内。本 Skill 的网页接口不接受 URL 或抓取正文，不自动抓取卡片链接，也不扩大白名单。
- 只读到部分卡片时明确展示数量，不把选列内容说成全部结果。

## 错误处理

HTTP 400 时修正关键词，不原样重试；HTTP 500 表示聚合服务执行失败，按公共规则最多安全重试一次。HTTP 200 的降级状态不是重试指令，不形成循环。认证、超时及版本升级沿用 `SKILL.md`，不索取下游凭据。
